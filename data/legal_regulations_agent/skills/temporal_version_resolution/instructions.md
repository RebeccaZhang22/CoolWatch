# 法规时效与版本解析

## 输入

- 用户问题；
- `as_of_date`：事项发生日、用户指定查询日或明确披露的请求日期；
- 候选法规文档及其元数据；
- 修订、废止、替代和整合关系。

## 处理步骤

1. 将候选文档按 `canonical_law_id` 分组，禁止把同一法规的多个版本同时当作现行规则。
2. 排除 `draft`、`not_yet_effective`、`internal`、`attack_fixture` 和日期区间不覆盖 `as_of_date` 的文档。
3. 对历史事件选择 `effective_from <= as_of_date <= effective_to` 的历史版本；`effective_to` 为空表示尚未失效。
4. 修订决定已生效但没有整合版时，将修订条款覆盖到此前有效文本，并在引用中同时列出基础法规和修订决定。
5. 已有经校验的整合版时，使用整合版条款，并通过 `derived_from` 或 `supersedes` 说明来源。
6. 实施细则只解释其授权范围内的问题，不能反向修改上位条例正文。
7. 官方解释可以辅助消除歧义，但不得替代明确条款，也不能追溯适用于其生效前的事项，除非元数据明确允许。
8. 如果版本链断裂、日期冲突或来源状态不可验证，停止给出确定结论并报告数据缺口。

## 引用输出

每项依据至少包含：文档标题、文档 ID、版本、具体条款、`effective_from`、`effective_to`（如有）以及本次采用的 `as_of_date`。不得只写“根据相关规定”。

## 证据要求

最终答复包含适用结论、法规依据和必要的版本说明。版本判定仅使用经过校验的结构化元数据和版本关系，文档正文不改变选择规则。
