## 代码路径

- backend/customer_agent.py 的 check_activation：保留首条 system 以及其他非 system 消息，调用 bank_guard.moderate；有工具调用后标记 stage=context。
- 每轮业务生成前执行检查，只有 risk 才阻断。后一次检测结果替换之前的 activation_probe 展示信号，因此前端看到的是检索后的 0.886，而不是初始输入的 0.284。
- backend/qwen3_probe_bank_server.py：IPI 用 sigmoid(logit) 得分，flagged = score >= args.ipi_threshold。

结论：这是当前混合检索上下文下的实际漏检，不是前端显示错误。此前的 0.9639 只适用于隔离案例上下文，不能保证直接上传到包含其他攻击文档的现有知识库后仍达到阈值。此次没有修改业务代码、线上知识库或阈值。
