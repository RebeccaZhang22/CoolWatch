已有智能体接入防护

无需迁移或重新搭建智能体。将智能体当前的完整消息列表发送到检测接口，根据返回的 action 决定继续执行还是立即拦截。

接入方式 调用时机 接口说明 请求参数 响应参数 错误码

接入方式

ProspectMonitor 作为已有智能体旁路的安全检测服务工作。你的业务模型、System Prompt、RAG 和工具调用方式都可以保持不变，只需在关键执行节点调用检测接口。

已有智能体保留原有配置
提交上下文messages + tools
安全检测多个 Probe 并行
读取 actionpass / block
继续或中止由业务侧执行
检测接口不会替你调用业务模型，也不会改写原始消息。它只返回风险判断，你的智能体仍然掌握最终执行权。

调用时机

  1. 模型调用前：在用户消息加入上下文后检测一次。若返回 block，不要把该轮请求发送给业务模型。
  2. 工具返回后：把工具或 RAG 结果以 tool 消息加入上下文，再检测一次，防止外部内容中的间接提示词注入进入后续模型调用。
  3. 继续生成前：只有检测结果为 pass 时，才让智能体继续调用模型或执行下一步工具。
每次传入当前完整消息列表。你不需要预先判断风险属于哪一类，服务端会让所有已启用的 Probe 共同检查同一份上下文。

接口说明

POST/v1/moderations

接口同步返回检测结果。请求头使用开发者中心生成的 API Token：

Authorization: Bearer YOUR_TOKEN
Content-Type: application/json

请求参数

字段类型必填说明
messagesarray是当前完整消息列表，按真实执行顺序传入，不要只截取最后一个 Query。
messages[].rolestring是支持 developer、system、user、assistant、tool。
messages[].contentstring是当前版本支持文本内容。
messages[].reasoning_contentstring否需要参与检测的推理文本。
toolsarray否智能体本轮可用的工具定义，格式与模型调用时保持一致。

请求示例

{
  "messages": [
    {"role": "system", "content": "你是企业客服助手。"},
    {"role": "user", "content": "请查询我的订单状态。"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {"name": "lookup_order", "description": "查询订单"}
    }
  ]
}

响应参数

字段说明
actionpass 表示可以继续；block 表示至少一个风险检测已触发，应中止后续执行。
per_risk内容安全、提示词泄漏和间接提示词注入的风险分数、阈值及是否触发。
per_entry各个 Probe 的原始分值，便于审计和排查。
triggered_entries本次超过阈值的 Probe 列表。
request_id请求追踪 ID，可与开发者中心调用日志对应。
usage本次检测的输入 Token 与计费单位。
latency_ms排队、检测和总耗时。

响应示例

{
  "id": "mod_...",
  "request_id": "req_...",
  "detector_model": "qwen35-2b",
  "action": "pass",
  "per_risk": {
    "harmful": {"score": 0.08, "threshold": 0.50, "flagged": false},
    "prompt_leakage": {"score": 0.11, "threshold": 0.50, "flagged": false},
    "ipi": {"score": 0.06, "threshold": 0.50, "flagged": false}
  },
  "triggered_entries": [],
  "usage": {"input_tokens": 32, "unit": "1k_input_tokens"},
  "latency_ms": {"total": 41.7}
}

处理规则

if result["action"] == "block":
    # 停止调用模型或工具，向用户返回统一安全提示
    stop_agent()
else:
    # 保持原有智能体流程
    continue_agent()

错误码

HTTP 状态码含义建议处理
400JSON、消息角色或字段格式不正确修正请求后重试。
401API Token 缺失或无效检查 Bearer Token，必要时在本页重置。
413输入超过服务限制缩短上下文后重新检测。
429检测服务暂时过载读取 Retry-After，退避后重试。
503 / 504检测服务不可用或超时暂停智能体后续执行并重试，避免绕过防护。
