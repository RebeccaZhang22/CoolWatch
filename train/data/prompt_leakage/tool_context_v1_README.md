# 工具上下文泄露训练补充集 v1

针对 RAG 原文导出请求在工具上下文中漏检的问题，新增 2,680 条样本。
生成器：`scripts/activation_probe/prepare_tool_context_leakage.py`，种子 20260918。
所有业务档案均为合成内容。

| 来源 | 数量 | 处理 |
|---|---:|---|
| 工具上下文成对样本 | 1,120 | 中文多业务场景、成对正负例、检索前与检索后视图 |
| 原 v3 样本添加工具定义 | 1,200 | 正负各半，保留原始问题、标签、组和划分 |
| 原 LeakGauge RAG 样本迁移为工具返回 | 360 | 正负各半，将已有 context 移到 tool 消息，不截断 |

| 划分 | 正例 | 负例 | 总计 |
|---|---:|---:|---:|
| train | 644 | 1,028 | 1,672 |
| val | 188 | 316 | 504 |
| test | 188 | 316 | 504 |

正例覆盖离线质检、调试快照、合成资料例外、直接导出等要求完整获取受保护上下文的请求。
负例覆盖限定范围的问答、机器可读的正常答案、用户自有文本处理、允许的公开材料原文引用。
同一上下文同时用于正负请求，避免内部标记或工具存在本身成为标签线索。

新增合成场景按业务领域、场景组与攻击措辞家族划分；同组所有视图和正负例保持在同一划分。
已有样本的增广严格保留原划分。构建时检查 ID 唯一、组/完整对话/用户查询无跨划分重复。
验证集和测试集仍属合成开发评估，同一场景的多个视图相关，不能当成完全独立的生产请求。
部分“用户自有文本处理 + 工具结果”的负例是刻意构建的反事实困难样本。

`external_audits/reported_rag_tool_context.jsonl` 中的 5 条是已知问题回归：
原句检索前 1 条、真实正文检索后 2 条、仅正常问题 2 条。
它们只用于模型选择完成后的评估，不进入训练或阈值选择；也不作为未知攻击泛化的证据。

实际训练保留原 `protected_asset_theft v3` 的全部 19,580 条样本及固定划分，再追加本数据。
合计 22,260 条，13,228 train / 3,972 val / 5,060 test。
原始来源和哈希见 `manifest.json` 及候选探针目录中的 `dataset_manifest.json`。
